## Static analysis（静态分析）

在编译原理中，**静态分析（Static Analysis）是指在不实际运行程序的情况下，通过分析源代码或程序的中间表示，检查程序是否符合某些规则，并推断程序的性质**。

首先看一段 C 代码：

```
int main() {
    int a = 10;
    int b = "hello";
    return a + b;
}
```

从词法分析和语法分析的角度来看：

- 词法分析（Lexical Analysis）：`int`、`b`、`=`、`"hello"` 都是合法的 Token。
- 语法分析（Syntax Analysis）：`int b = "hello";` 符合变量声明及初始化的语法结构。
- 静态语义分析（Static Semantic Analysis）：发现字符串不能直接用于初始化 `int` 类型变量，因此报告类型错误。

这就引出了一个重要的问题：

***一段代码即使在词法和语法上完全合法，也不代表它在语义上合法***。静态分析最基本、最容易理解的是类型检查和作用域分析。

> 静态分析和动态分析有什么区别？两者最根本的区别是：是否需要实际执行程序。

## Intermediate Representation(s) （中间表达形式）

在这里中间表达形式起到一个连接 **源代码** 与 **目标代码** 的作用，这么做的一个重要原因就是轻松支持源语言在多个平台（这里的平台指的是 不同 的CPU 指令架构集）的可用性。

使用共享的中间表示形式可以显著降低这种复杂性。你需要为每种源语言编写一个生成中间表示形式的代码；同时，还需要为每种目标架构编写相应的代码。这样，通过将各种组件组合起来，就可以实现各种可能的组合方式。

## Code Generation（代码生成）

代码生成指的是将程序转换成能够被机器实际运行的形式。

这里一般有两个选择：一个是直接生成机器码（能够被CPU直接执行）；另外一个是生成字节码，也就是虚拟机代码。虚拟机代码一般在在虚拟机中执行，就比如JVM Bytecode、Python Bytecode，这一类编程语言通常具有良好的平台通用性。
