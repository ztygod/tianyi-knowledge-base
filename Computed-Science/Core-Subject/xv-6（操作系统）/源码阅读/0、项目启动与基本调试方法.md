### 项目依赖

我的电脑是 Apple Silicon Mac，具体依赖如下：
- Make：读取 `Makefile`，按依赖关系执行构建和启动命令
- riscv64-elf-gcc：把 C 和汇编源码编译成 RISC-V 机器代码，在项目中具体是编译 xv6 内核和用户程序
- **QEMU**：`qemu-system-riscv64`，模拟 RISC-V CPU、内存、磁盘和串口等硬件，真正执行 xv6；同时提供 GDB 远程调试接口
- **RISC-V GDB**：`riscv64-elf-gdb`，连接 QEMU，控制执行并检查内部状态，设置断点、单步执行、查看变量、寄存器、内存和调用栈

### 启动调试命令

打开两个终端，按下面的顺序操作。

1. **终端 A：启动 xv6，等待调试**
```Plain
cd /Users/tianyi/zhoutianyi-project/xv6-riscv
make qemu-gdb CPUS=1
```

它会编译项目、启动 QEMU，并暂停 CPU 等待 GDB。保持这个终端运行。

如果只想正常运行，不调试，则使用：

```Plain
make qemu CPUS=1
```

2. **终端 B：启动 GDB 并连接**

```Plain
cd /Users/tianyi/zhoutianyi-project/xv6-riscv
riscv64-elf-gdb -nx -x .gdbinit
```

下面的调试命令都在终端 B 的 `(gdb)` 提示符后输入。

3. **观察内核启动**

```Plain
break main
continue
```

停在内核 `main()` 后，可以逐步执行：

```Plain
list
next
step
bt
info registers
```

| 命令                  | 作用                 |
| ------------------- | ------------------ |
| break main / b main | 在函数入口设置断点          |
| continue / c        | 继续运行，到下一个断点暂停      |
| next / n            | 执行下一行，跳过函数内部       |
| step / s            | 执行下一行，进入函数内部       |
| finish              | 执行到当前函数返回          |
| list / l            | 显示源码               |
| bt                  | 查看调用栈              |
| p 变量名               | 查看变量               |
| info registers      | 查看寄存器              |
| x/10i $pc           | 查看当前位置开始的 10 条汇编指令 |
| si                  | 执行一条机器指令           |
| info breakpoints    | 查看断点列表             |
| delete breakpoints  | 删除所有断点             |

4. **观察系统调用**
删除之前的断点，在当前项目的系统调用分发位置设置断点：

```Plain
delete breakpoints
break kernel/syscall.c:143
continue
```

停下后，查看当前进程和系统调用编号：

```Plain
p p->pid
p p->name
p num
p/x p->trapframe->a7
bt
```

此处 `p` 和 `num` 已经赋值。`num` 是系统调用编号，例如 `7` 表示 `exec`，`16` 表示 `write`。

5. **恢复运行与退出**

让 xv6 正常运行到 shell：

```Plain
disable breakpoints
continue
```

然后在终端 A 输入：

```Plain
ls
echo hello
```

需要再次观察时，在**终端 B 按 Ctrl+C**暂停，再设置或启用断点：

```Plain
enable breakpoints
continue
```

结束调试，在 GDB 输入 `quit`；退出 QEMU，在终端 A **按 Ctrl+A，松开，再按 x**。
