### 2 、I/O and File descriptors

- 文件描述符（File Descriptor，FD）：一个非负整数，作为进程访问内核管理的文件、管道和设备等 I/O 对象的句柄。**文件描述符不是文件本身，而是进程用来找到内核 I/O 对象的索引**。
- I/O（输入/输出）：进程通过操作系统读取或写入数据的过程。

最重要的设计思想：**xv6 将不同类型的** **I/O** **对象统一抽象成**字节流，让程序通过 **`read()`** **和** **`write()`** **操作它们，而不必关心底层究竟是普通文件、终端还是管道。这也是实现I/O重定向的原理（也是fork和exec分开的原因）。**

对于 xv6，通常约定：

| FD    | 名称     | 默认用途            |
| ----- | ------ | --------------- |
| 0     | stdin  | 标准输入，从终端读取      |
| 1     | stdout | 标准输出，向终端打印      |
| 2     | stderr | 标准错误，输出错误信息     |
| 3 及以后 | 普通描述符  | 文件、管道或其他 I/O 对象 |

注意，这些是约定，不是固定绑定。例如，fd 1 可以被重定向到文件。

```c
int p[2];
char *argv[2];

argv[0] = "wc";
argv[1] = 0;

pipe(p);

if (fork() == 0) {
    // 子进程
    close(0);  // 释放文件描述符 0（标准输入）
    dup(p[0]); // 复制管道读端 p[0]，使文件描述符 0 指向管道读端，
               // 从而将子进程的标准输入重定向到管道。

    close(p[0]);

    // 必须关闭子进程持有的管道写端。
    // 如果没有关闭 p[1]，即使父进程关闭了写端，
    // 内核仍然认为存在写入者，wc 就无法收到 EOF，
    // 可能一直阻塞在 read()。
    close(p[1]);

    // 执行 wc，从标准输入读取数据并统计。
    exec("/bin/wc", argv);
} else {
    // 父进程
    close(p[0]);

    // 向管道写入数据。
    write(p[1], "hello world\n", 12);

    // 关闭管道写端。
    // 只有当所有写端都关闭，并且缓冲区中的数据都被读取完后，
    // 读端才会收到 EOF（read() 返回 0）。
    // 因此，关闭 p[1] 相当于告诉子进程：
    // 数据已经写完，不会再向管道发送数据。
    close(p[1]);
}
```

### 3、Pipes

- 管道（Pipe）本质上是由操作系统内核维护的一块缓冲区，以及围绕它实现的一套读写和同步机制，用于在进程之间传输数据。

```C
int p[2];
pipe(p);

write(p[1], "hello", 5);

char buf[6] = {0};
read(p[0], buf, 5);

printf("%s\n", buf); // hello
```
