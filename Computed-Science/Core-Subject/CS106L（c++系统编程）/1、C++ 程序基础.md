## **C++ 类型系统（Type System）**

### **基本数据类型**

C++ 是静态类型语言，变量的类型通常在编译阶段就已经确定。**类型不只是对数据的分类，更是编译器解释和操作数据的一种规则。**
![[Pasted image 20261126153652.png|557]]
### `auto` **类型推导**

现代 C++ 中，可以使用 `auto` 让编译器自动推导变量类型。

```java
auto a = 10;       // int
auto b = 3.14;     // double
auto c = 3.14f;    // float
auto d = true;     // bool
auto e = 'A';      // char
```

需要注意，C++ 的 `auto` 并不意味着动态类型。

```java
auto x = 10;
x = 3.14;
```

这里 `x` 仍然是 `int` 类型，赋值时会发生类型转换，最终存储的值为 `3`。

### `size_t` **类型**

**`size_t` 是一种无符号整数类型**，通常用于表示对象大小、容器长度以及索引。尤其需要注意无符号整数的下溢问题。

```java
std::size_t n = 0;
n = n - 1;
```

执行 n - 1 后的结果：18446744073709551615。发生无符号整数回绕，结果变为该类型的最大值。

这也是为什么下面的循环存在问题：

```java
for (size_t i = 10; i >= 0; --i) {
    std::cout << i << '\n';
}
```

由于无符号整数永远不会小于零，所以退出条件始终不成立。

## **变量初始化（Initialization）**

### **四种常见初始化形式**

```c++
int a = 10;    // 拷贝初始化
int b(10);     // 直接初始化
int c{10};     // 直接列表初始化
int d = {10};  // 拷贝列表初始化
```

### **为什么现代 C++ 经常使用** `{}`

C++11 引入了列表初始化，其中一个重要优点是能够防止窄化转换（Narrowing Conversion）。

```c++
int a = 3.14;  // 合法，结果为 3，可能产生警告
int b(3.14);   // 合法，结果为 3，可能产生警告
int c{3.14};   // 编译错误
```

## **命名空间（Namespace）**

假设两个不同的开发者分别开发了两个库，并且都定义了 `add` 函数。

```java
int add(int a, int b) {
    return a + b;
}

int add(int a, int b) {
    return a + b + 10;
}
```

编译器无法允许这两个相同签名的函数定义在同一个作用域中。C++ 使用命名空间来组织名称，解决命名冲突。

```java
namespace math {
    int add(int a, int b) {
        return a + b;
    }
}

namespace custom {
    int add(int a, int b) {
        return a + b + 10;
    }
}
```

调用时：

```c++
int main() {
    std::cout << math::add(1, 2) << '\n';   // 3
    std::cout << custom::add(1, 2) << '\n'; // 13
}
```

**`std` 就是 C++ 标准库使用的命名空间。**

### `using namespace std` **是什么**

你可能经常看到这样的代码：

```c++
#include <iostream>
using namespace std;

int main() {
    cout << "Hello" << endl;
}
```

它的作用是使命名空间 `std` 中的名称可以参与当前作用域中的非限定名称查找，从而不需要每次都写 `std::`。

### **类型别名（Type Alias）**

```c++
using Matrix = std::vector<std::vector<double>>;
```

这不是引入命名空间，而是为一个已有类型创建别名。

之后就可以直接使用：

```c++
Matrix matrix;
```

相当于：

```c++
std::vector<std::vector<double>> matrix;
```


## **头文件与源文件**

随着项目规模扩大，我们不可能把所有代码都写在 `main.cpp` 中。这里有两个核心概念：声明（Declaration）和定义（Definition）。

### **声明与定义**

声明告诉编译器某个名称及其类型等信息。

```c++
int add(int a, int b);
```

这段代码告诉编译器，有一个函数叫 `add`，接收两个 `int` 参数，返回一个 `int`。

而定义提供了函数的具体实现。

```c++
int add(int a, int b) {
    return a + b;
}
```

可以把声明理解为接口，把定义理解为实现。

### `#include` **的本质是什么？**

从预处理的角度来看，`#include` 可以近似理解为把指定头文件的内容展开到当前源文件中。

```c++
#include "math.h"
```

在预处理之后，编译器就能看到 `math.h` 中的函数声明。但需要注意，包含头文件并不代表已经编译或链接了对应的 `.cpp` 文件。

### **Header Guard（头文件保护）**

```c++
#ifndef MATH_H
#define MATH_H

// 声明

#endif
```

**它用于防止同一个头文件在一个翻译单元中被重复展开**。现代项目也经常使用：

```c++
#pragma once

namespace math {
    int add(int a, int b);
}
```

`#pragma once` 更加简洁，被主流编译器广泛支持，但它不是 ISO C++ 标准规定的特性。

## **C++ 的编译与链接**

### **第一阶段：预处理（Preprocessing）**

主要处理：

- 展开 `#include`。
- 替换宏 `#define`。
- 处理条件编译指令。
- 移除注释。

### **第二阶段：编译（Compilation）**

主要负责词法分析、语法分析、语义分析、中间表示生成、优化以及目标代码生成。
![[Pasted image 20261126162502.png|676]]
### **第三阶段：汇编（Assembly）**

汇编器负责将汇编代码转换成机器码，并生成目标文件（Object File）。

```
clang++ -std=c++17 -c main.cpp -o main.o
```

### **第四阶段：链接（Linking）**

![[Pasted image 20261126162730.png|556]]链接器会解析目标文件之间的符号引用，并进行必要的重定位，最终生成可执行程序。

**头文件解决的是编译阶段能否认识某个名称的问题，链接器解决的是符号引用能否找到对应定义的问题。**

### **翻译单元（Translation Unit）**

一个 `.cpp` 文件经过预处理，展开其包含的头文件并处理宏等指令后，形成一个翻译单元。

通常，每个 `.cpp` 文件都是独立编译的。

这就是为什么大型 C++ 项目不必在修改一个源文件之后重新编译所有源文件。只需要根据依赖关系重新编译受影响的翻译单元，再进行链接即可。
